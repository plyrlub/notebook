# 网络底座总览

> **Java 网络底座域**：应用进程的**网络 IO 与 Web 服务器**层。区别「中间件」（独立业务支撑进程）、「框架」（应用业务框架）、「微服务架构」（组合层）。
> 覆盖：IO 模型/NIO/Netty（网络通信）、Tomcat（Web 服务器）。

## 1. 网络底座域的定位与划分

**一句话**：网络底座 = **应用进程的通信底盘**——它既是"网络 IO 怎么读写"（NIO/Netty），也是"Web 请求怎么被服务进程接住"（Tomcat）。区别：

| 维度 | 网络底座（本域） | 中间件 | 框架 |
|---|---|---|---|
| 职责 | 网络 IO / 服务器进程 | 业务支撑独立服务 | 应用业务/数据框架 |
| 形态 | 库(Netty) + 服务器(Tomcat) | 独立部署服务 | 应用内嵌库 |
| 例子 | Java NIO、Netty、Socket、Tomcat | Nacos、Apollo、Seata | Spring、MyBatis、Dubbo |

> ⚠️ 为什么 tomcat/netty/NIO 单独成域而不是塞进"框架"或"中间件"：
> - 对 **中间件**：tomcat 是 Web 服务器、是被服务/应用的"外层容器"，不是业务支撑服务（配置/协调/消息）——两类语义不同。
> - 对 **框架**：NIO/Socket/Netty 首先是**网络传输层**，Dubbo/gRPC/Feign 才用它们做**上层调用框架**。网络底座是后者的"底座"。

## 4. 与中间件/框架/微服务的边界

```
应用进程 = 框架(业务) + 网络底座(IO/Web容器)     ← 本域在"进程通信/服务接收"
独立进程 = 中间件 (nacos/apollo/seata)
组合层   = 微服务架构 (注册/网关/治理) 引用中间件+框架
                         数据访问层 (ORM/分库分表)
网络底座典型关系: 应用(Tomcat接HTTP) → 业务(框架) → 数据(数据访问层/中间件)
```

> 💡 **依赖方向**：中间件/框架可以依赖网络底座（如 Dubbo 用 Netty）；网络底座不依赖业务中间件。本域是 Java 网络实力的基础层。
