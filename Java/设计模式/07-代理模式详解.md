# 代理模式详解

> 本篇拆解代理模式：静态代理 → JDK 动态代理 → CGLIB，讲清「为什么动态代理能增强代码」，并结合 Spring AOP 印证。这是结构型里最重要、面试最高频的一个。

## 📋 总纲

代理模式的核心：**不直接访问目标对象，而是通过一个「代理」去访问，在代理里增加额外处理（权限、缓存、日志、延迟……）**，目标类本身不改一个字。它是实现 AOP（面向切面）的基石。

## 1. 是什么 / 为什么用（原理）

**问题**：要给某个业务方法加「日志/事务/权限校验」。直接改原类会侵入业务代码、重复散落。

**解决思路**：创建一个**代理对象**，它和原对象实现同一接口。调用方通过代理调方法，代理在调用前后插入增强逻辑，再转调真正目标。

**生活类比**：**经纪人/中介**——明星（目标）不直接接代言，都由经纪人（代理）谈价、把关、排期。明星本人不变，经纪人负责「外围处理」。

## 2. 静态代理

编译期就写好代理类，一个目标一个代理类，写死绑定。

```java
// 目标接口与被代理目标
public interface Service {
    void doWork();
}
public class RealService implements Service {
    public void doWork() { System.out.println("真实业务工作"); }
}

// 静态代理：同接口，持有目标，方法内加增强
public class ServiceProxy implements Service {
    private final Service target;

    public ServiceProxy(Service target) { this.target = target; }

    @Override
    public void doWork() {
        System.out.println("【增强】调用前记录日志");
        target.doWork();                          // 转调真实目标
        System.out.println("【增强】调用后记录日志");
    }
}
```

**调用**：把 `ServiceProxy` 当接口用，能力与目标相同但多了增强。

**说明**：静态代理**每代理一个目标就要写一个类**，目标一多、方法一多就爆炸。而且它「编译期写死」，要增强的逻辑变了又得改代理类。引出动态代理。

## 3. JDK 动态代理

**运行期**根据接口动态生成代理对象，只需一个通用的 `InvocationHandler`，不用为每个目标写代理类。

### 3.1 核心代码

```java
import java.lang.reflect.*;

public class JdkProxy {
    public static Service create(Service target) {
        // 三个参数：类加载器、目标实现的接口数组、调用处理器
        return (Service) Proxy.newProxyInstance(
                target.getClass().getClassLoader(),
                target.getClass().getInterfaces(),   // 目标必须实现接口！
                new InvocationHandler() {
                    @Override
                    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
                        System.out.println("【JDK代理】调用前增强: " + method.getName());
                        Object result = method.invoke(target, args);   // 反射调用真实目标方法
                        System.out.println("【JDK代理】调用后增强");
                        return result;
                    }
                });
    }
}

// 使用
Service proxy = JdkProxy.create(new RealService());
proxy.doWork();
```

### 3.2 原理说明

- `Proxy.newProxyInstance` 在**运行期动态生成**一个实现目标接口的代理类（字节码生成），无需手写。
- 所有通过代理接口调用的方法都进 `invoke()`，在此统一增强，再用**反射** `method.invoke(target, args)` 转调真目标。
- **限制**：JDK 动态代理**只能代理「接口」**。目标若没有实现接口（纯类），没法用接口反射 → 需要 CGLIB。

## 4. CGLIB 代理

通过**继承目标类**生成子类代理，不需要接口。Spring 在目标类**没有实现接口**时就用 CGLIB。

```java
import net.sf.cglib.proxy.*;

public class CglibProxy {
    public static Object create(Class<?> targetClass) {
        Enhancer enhancer = new Enhancer();
        enhancer.setSuperclass(targetClass);         // 以目标类为父类
        enhancer.setCallback((MethodInterceptor) (obj, method, args, proxy) -> {
            System.out.println("【CGLIB】调用前增强");
            Object result = proxy.invokeSuper(obj, args);  // 调用父类(目标)方法
            System.out.println("【CGLIB】调用后增强");
            return result;
        });
        return enhancer.create();                    // 返回目标类的子类代理
    }
}
```

**说明**：
- CGLIB 用 `Enhancer` **动态生成目标类的子类**，靠「继承 + 重写方法」来实现增强 → 不需要接口。
- `proxy.invokeSuper(obj, args)` 调用父类（真正的目标类）方法。
- **限制**：`final` 类/方法无法被 CGLIB 子类化重写 → 不能代理。

## 5. 两种动态代理对比（Spring AOP 选型依据）

| 维度 | JDK 动态代理 | CGLIB |
|---|---|---|
| 原理 | 动态实现**接口** | 动态**继承**目标类 |
| 是否需接口 | 必须 | 不需要 |
| 目标类要求 | 有接口 | 非 final 类、方法非 final |
| 生成方式 | `Proxy.newProxyInstance` | `Enhancer` |
| 场景 | AOP / RPC / 大量框架 | 目标无接口时 |
| Spring 默认 | 早期默认 | **Spring Boot 默认 CGLIB**（无接口也能代理） |

**Spring 关键点**：早期 Spring AOP 默认 JDK 代理，目标无接口会退化；**Spring Boot 默认启用 CGLIB**，即使有接口也用继承代理，避免接口代理的限制。

## 6. Spring AOP 与代理模式（现实印证）

- Spring AOP 从根本上就是**动态代理**的实现：切面（Aspect）、通知（Advice）、切点（Pointcut）编译成对方法的增强逻辑，通过生成代理注入。
- 事务 `@Transactional`、缓存 `@Cacheable`、`@Async` 等注解，本质都是**代理增强**。
- Spring 在哪选 JDK 还是 CGLIB：目标有接口 → 可用 JDK；无接口 → CGLIB；Boot 默认 CGLIB。

## 7. 代理 vs 装饰器 vs 适配器（必考三重对比）

| | 代理 Proxy | 装饰器 Decorator | 适配器 Adapter |
|---|---|---|---|
| 意图 | 控制访问/加外围处理 | 动态扩展功能行为 | 接口转换 |
| 接口 | 与目标**相同** | 与目标**相同** | **不同**（转接口） |
| 是否改功能 | 通常不改（加控制） | **追加功能** | 不改（仅转换） |
| 典型 | AOP、远程、延迟加载 | IO 流包装、加日志职责 | InputStreamReader |
| 本质 | 保护/拦截 | 叠加能力 | 翻译 |

## 8. 最佳实践

1. 优先用 Spring 容器装配代理（@Transactional/@Aspect），少手写。
2. 手写动态代理时，明确目标有没有接口 → 有则 JDK，无则 CGLIB。
3. 被代理的方法**不要是 final/static/private**（CGLIB 无法重写，JDK 反射也不走接口）。
4. **Spring 内部调用陷阱**：同类内 this 调方法不经过代理（自调用失效），需注入自身或 AOP 上下文。

## 9. 常见踩坑

- 代理类 final 方法代理无效。
- Spring 自调用（this 调用）不触发 AOP 增强。
> 相关横向下节通用原则见 [99-设计模式踩坑记录](99-设计模式踩坑记录.md)

## 10. 小结

- 静态代理写死每个目标，动态代理（JDK/CGLIB）运行期生成通用代理。
- JDK 代理要接口，CGLIB 代理靠继承，**没接口用 CGLIB**。
- Spring AOP / @Transactional 就是代理模式，**Boot 默认 CGLIB**。
- 代理/装饰器/适配器三重区分：代理加控制、装饰器加功能、适配器转接口。
