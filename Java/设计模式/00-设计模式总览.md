# 设计模式总览

> 本文是设计模式系列的总入口，含分类体系、版本基线、前置知识、学习路径与选型心法。单篇详解见文档导航。

## 📋 总纲

设计模式是**前人解决特定场景问题的高度抽象、可复用的经验解**。它不是语法，而是一套「面向对象 + 可维护 + 可扩展」的组合拳。掌握设计模式的核心不是背 23 个名字，而是建立**「场景-问题-方案」的映射能力**：读代码时能认出模式，写代码时能按需套用而不滥用。

## 1. 软件版本基线

- JDK：17（本系列代码基于 JDK 17 编译运行，涉及序列化/反射等特性以该版本行为为准）
- 构建：无依赖，纯 Java 单文件代码片段，可直接 `javac` 编译、`java` 运行
- 说明：模式与语言版本弱相关，重点在结构与思想；实现层面标注 JDK 版本敏感的写法（如枚举单例、记录类）

## 2. 前置知识

学习设计模式前需先掌握：

- **面向对象三大特性**：封装、继承、多态（模式到处在使用多态做「面向接口编程」）
- **接口 / 抽象类**：何时用接口（能力契约）、何时用抽象类（骨架复用）
- **组合优于继承**：装饰器、策略等模式的核心思想来源
- **Java 基础**：反射、序列化、枚举、泛型（单例/原型/工厂会用到）
- 可选：Spring 基础（Spring 是设计模式的大型实践现场，第二三阶段会横向映射）

## 4. 学习目标

学完本系列你能做到：

1. 说出 23 种 GoF 模式的分类归属（创建/结构/行为），并说明分类依据
2. 对每个常用模式，讲清「解决的问题、UML/Mermaid 结构、适用场景、易错点、代价」
3. 写出可运行的单例、工厂、建造者等关键实现，并能辨析线程安全、序列化等边界
4. 读 Spring 等框架源码时，能识别出背后的设计模式及其意图
5. 在建模自己的业务时，能判断「该不该用模式、用哪个」，避免为了模式而模式

## 5. 最佳学习路径

1. **先懂分类**：分清三种类型解决的问题（创建对象 / 组合对象结构 / 对象间协作），这是记忆的骨架
2. **从创建型入手**：单例 → 工厂 → 建造者 → 原型，最简单、最常用、面试最高频
3. **吃透三个「核心中的核心」**：单例、工厂、代理（结构型）——几乎所有面试和框架都有它们
4. **建立横向对比**：工厂方法 vs 抽象工厂、装饰器 vs 代理 vs 适配器、策略 vs 状态、观察者 vs 发布订阅——对比题是面试重灾区
5. **落到框架印证**：Spring 里遍地是模式（Bean 工厂=工厂、AOP=代理、事件=观察者、JdbcTemplate=模板方法），读到模式想到代码
6. **警惕过度设计**：模式是「药」，说明场景里有病才能用，无条件套用是反模式

## 6. 设计模式分类总表（23 种 GoF）

| 类型 | 解决的问题 | 代表场景 | 模式清单 |
|---|---|---|---|
| **创建型**（5） | 隐藏对象创建细节 | 单例、多条件构造 | 单例、简单工厂/工厂方法、抽象工厂、建造者、原型 |
| **结构型**（7） | 组合类/对象形成更大结构 | 接口适配、扩展功能 | 适配器、代理、装饰器、桥接、组合、外观、享元 |
| **行为型**（11） | 对象之间的职责分配与协作 | 算法替换、状态流转、通知 | 策略、模板方法、观察者、状态、责任链、命令、迭代器、中介者、备忘录、访问者、解释器 |

### 6.1 一句话辨型（面试记忆法）

- 想「**怎么产生对象**」→ 创建型
- 想「**怎么组织对象结构**」→ 结构型
- 想「**对象之间怎么协作**」→ 行为型

### 6.2 常用度分层（工程实践优先级）

- **高**（必会）：单例、工厂方法、策略、模板方法、观察者、代理、装饰器、适配器
- **中**（常遇）：抽象工厂、建造者、责任链、状态、外观、组合、桥接
- **低**（精而简即可）：原型、享元、备忘录、中介者、访问者、解释器、迭代器、命令

## 7. 演进规划

- 阶段一（本批）：总览 + 创建型 5 种 + 踩坑库
- 阶段二：结构型 7 种（适配器/代理/装饰器/桥接/组合/外观/享元）
- 阶段三：行为型 11 种（策略/模板/观察者/状态/责任链/命令/迭代器/中介者/备忘录/访问者/解释器）

## 8. 选型建议与安全风险

- 设计模式不引入任何第三方安全依赖；注意单例的**反射/反序列化破坏**（见 [01-单例模式详解](01-单例模式详解.md)），原型的**深度克隆可能产生敏感引用**（clone 深浅需审慎）
- 原则：**优先用简单写法**，只有确有其病再上模式；模式是手段不是目的
