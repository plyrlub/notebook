# 设计模式踩坑记录

> 本库统一收录设计模式系列的踩坑，编号规则 `#类型.序号`。跨文档引用：`> 参考踩坑：[#1.1 单例被反射/反序列化破坏](99-设计模式踩坑记录.md)`（带锚点）。

## #1 单例模式

### #1.1 单例被反射 / 反序列化破坏
- **现象**：通过 `Constructor.newInstance()` / 反序列化可再创建一个实例，单例失效；懒汉线程不安全时多线程拿到不同实例。
- **原因**：反射不检查私有构造器；序列化默认走 `readResolve` 前会新建对象；懒汉模式 if 判断后创建存在竞态。
- **解决**：枚举单例天然免疫；非枚举可用「私有构造器抛异常 + `readResolve()` 返回原实例」双保险；懒汉加锁、DCL 时字段加 volatile。

### #1.2 DCL（双重检查锁）必须加 volatile
- **现象**：并发下拿到「半初始化」对象，字段为默认值。
- **原因**：`instance == null` 检查时，其他线程可能读到未完成构造的引用，且指令重排可能让引用先于字段赋值。
- **解决**：`private static volatile Singleton instance;`，或直接用静态内部类方案规避。

## #2 工厂模式

### #2.1 工厂开了就能扛？（过度设计误报）
- **现象**：只有一个产品类，也套了工厂 + 接口，代码膨胀。
- **原因**：把工厂当「标配」，而不是当「解决创建逻辑集中/扩展开放」的方案。
- **解决**：工厂的价值在于「**客户端不依赖具体类、新增类型不改客户端**」；没有这个诉求就用 `new`。用简单工厂兜底，别为仪式感上抽象工厂。

## #3 建造者模式

### #3.1 必填字段被漏 settable 绕过
- **现象**：建造者把所有字段都做成链式 setter，必填项没过校验。
- **原因**：使用 `builder()` 后构造器不再负责必填校验。
- **解决**：必填字段作为 `builder(必填参)` 的参数传入，或 build() 末尾统一 `validate()`。

## #4 原型模式

### #4.1 浅克隆共享引用，改一个全变
- **现象**：clone 出的对象改某字段，原对象也跟着变。
- **原因**：`Object.clone()` 默认浅拷贝，引用类型字段只是复制了指针。
- **解决**：需要独立副本时做**深克隆**（重写 clone 手动克隆引用字段，或用序列化/JSON 拷贝），并明确这是期望的共享还是独立。
