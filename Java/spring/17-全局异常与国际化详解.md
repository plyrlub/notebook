## 一、全局异常处理 @ControllerAdvice

**为什么需要**：后端 Controller 每个方法都 try-catch 会四处重复。用一个全局处理器集中捕获 Controller 抛出的异常，统一转成响应格式。

| 注解 | 作用 | 记忆 |
| --- | --- | --- |
| `@ControllerAdvice` | 全局增强所有 Controller | 横切整个 Web 层 |
| `@RestControllerAdvice` | `@ControllerAdvice` + `@ResponseBody` | 现代 API 直接用这个 |
| `@ExceptionHandler(X.class)` | 指定捕获某异常类型 | 精确匹配优先于泛化 |

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)              // 业务异常：优先精确匹配
    public ResponseEntity<BaseResponse<Void>> handleBiz(BusinessException e) {
        return BaseResponse.error(e.getErrorCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class) // 参数校验异常
    public ResponseEntity<BaseResponse<Void>> handleValid(MethodArgumentNotValidException e) {
        String field = e.getBindingResult().getFieldError().getField();
        String msg = e.getBindingResult().getFieldError().getDefaultMessage();
        return BaseResponse.error(40001, field + ": " + msg);
    }

    @ExceptionHandler(Exception.class)                       // 兜底：未预期异常
    public ResponseEntity<BaseResponse<Void>> handleAll(Exception e) {
        log.error("未捕获异常", e);
        return BaseResponse.error(50000, "system error");
    }
}
```

**解析优先级**：Spring 按"异常类型与所属类层级最近者"匹配——`BusinessException` 的处理方法优先于 `Exception` 兜底，精确的在前。

> 详见 **Java参数校验详解**（见知识库） 的校验异常（`MethodArgumentNotValidException` 是 `@RequestBody` 校验失败抛出的核心异常）。

## 二、统一响应体 BaseResponse

前端判据与后端解耦：HTTP 状态码只表达"传输层成败"，**业务成败用 `code`**。

```java
public class BaseResponse<T> {
    private int code;       // 业务错误码，0=成功
    private String msg;     // 描述信息
    private T data;         // 业务数据

    public static <T> ResponseEntity<BaseResponse<T>> ok(T data) { ... }
    public static <T> ResponseEntity<BaseResponse<T>> error(int code, String msg) { ... }
}
```

```json
// 成功
{ "code": 0, "msg": "success", "data": { ... } }
// 业务失败（HTTP 仍 200，前端看 code）
{ "code": 1001, "msg": "用户不存在", "data": null }
```

> 两种流派：① **HTTP 状态码忠实**（400/401/404 逼真）② **全 200 + code 判定**（网关侧简单）。主流是 ②，`@ExceptionHandler` 里 `ResponseEntity` 可自定义 HTTP 状态，二者可兼用。

## 三、业务异常 BusinessException 与错误码设计

`BusinessException` 的好处：业务层 `throw` 一句即可，把"码 + 多语言文案 + 参数"职责隔离，不散落 `try-catch`。

```java
public class BusinessException extends RuntimeException {
    private final int errorCode;    // 数字错误码
    private final Object[] args;    // 占位参数（描述里 {0} {1}）

    public BusinessException(int errorCode, Object... args) {
        this.errorCode = errorCode;
        this.args = args;
    }
    public int getErrorCode() { return errorCode; }
    public Object[] getArgs() { return args; }
}
```

### 错误码两种风格

| 风格 | 示例 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **数字分段码**（主流） | `1001`、`40001`、`50000` | 前端 switch 稳定、跨语言、不分模块 | 可读性差，需查表 |
| **语义码** | `USER_NOT_FOUND`、`ORDER_LOCKED` | 可读、日志友好 | 团队内优先，前缀易长 |

**数字分段规范**（业界常见，前 1-2 位标层级/模块，后 2-3 位标具体错误）：

```
0      成功
1xxx   系统级（1=系统通用 2=配置 3=依赖服务）
2xxx   参数校验（2001 必填缺失 2002 格式错 2003 越界）
3xxx   权限/认证（3001 未登录 3002 token过期 3003 无权限）
4xxx   业务错误，按模块细分（41xx 用户 42xx 订单 43xx 商品）
5xxx   未知/兜底（50000 系统错误）
```

> 前端典型 usecase：`if(code===3001) 跳登录页; else if(code===3002) 刷新token; else 弹 msg`。这也是"数字码稳定，前端 switch 不受文案改版影响"的核心价值。

## 四、Spring 国际化 MessageSource 机制

### 4.1 概念

`MessageSource` 是 Spring 的**国际化消息抽象**，通过 `getMessage(code, args, locale)` 从 properties 按语言取文案。Spring Boot 自动装配了它（读 `spring.messages.*`）。

```java
String msg = messageSource.getMessage("user.notFound", new Object[]{"张三"}, locale);
// 中 → "用户张三不存在"；英 → "User 张三 not found"（按当前 Locale）
```

### 4.2 配置文件与解析顺序

```properties
# messages.properties                       默认语言（兜底）
user.notFound=User {0} not found
# messages_zh.properties                    中文
user.notFound=用户 {0} 不存在
# messages_en.properties                    英文
user.notFound=User {0} not found
```

```yaml
spring:
  messages:
    basename: messages        # 前缀，读 messages*.properties（默认）
    encoding: UTF-8           # 必须 UTF-8，否则中文乱码
    fallback-to-system-locale: false   # 建议 false：持久不可用时回退默认语言而非系统
```

**查找顺序**：`messages_<locale>.properties` → 缺失则回退默认 `messages.properties`（按 `Locale` 匹配如 de_DE → de → default）。

### 4.3 MessageSource 在代码中如何拿到

- 直接注入到任意 Bean（全局处理器、Service 都行）
- 模板处理器可用 `@Qualifier("messageSource")`
- 占位符 `{0} {1}` 与 `getMessage(code, args, locale)` 的 args 一一对应

```java
@Component
public class MyService {
    private final MessageSource messageSource;
    public MyService(MessageSource messageSource) { this.messageSource = messageSource; }

    public String greet(User u, Locale locale) {
        return messageSource.getMessage("user.notFound", new Object[]{u.getName()}, locale);
    }
}
```

## 五、完整贯通：抛异常 → 配置加载 → 多语言返回

### 5.1 配置（多语言错误码）

```properties
# messages_zh.properties
1001=用户不存在
1002=订单已被锁定
40001=参数[{0}]不合法

# messages_en.properties
1001=User not found
1002=Order is locked
40001=Parameter [{0}] invalid
```

### 5.2 业务层抛出

```java
@RestController
public class UserController {
    @GetMapping("/user")
    public BaseResponse<User> getUser(@RequestParam Long id, Locale locale) {
        User u = userService.findById(id);
        if (u == null) {
            throw new BusinessException(1001);      // 只抛码，不写文案
        }
        return BaseResponse.ok(u);
    }
}
```

> 注意 `Locale locale` 参数：Spring MVC 自动从请求解析当前 Locale（见 5.4），注入 handler 即可传进去。

### 5.3 全局处理器按 Locale 加载

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    private final MessageSource messageSource;
    public GlobalExceptionHandler(MessageSource messageSource) { this.messageSource = messageSource; }

    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<BaseResponse<Void>> handleBiz(BusinessException e, Locale locale) {
        String msg = messageSource.getMessage(String.valueOf(e.getErrorCode()), e.getArgs(), locale);
        return BaseResponse.error(e.getErrorCode(), msg);
    }
}
```

### 5.4 Locale 从哪来（多语言切换的根源）

| 方式 | 配置 | 说明 |
| --- | --- | --- |
| **请求头 `Accept-Language`**（默认） | 无 | 浏览器/客户端带 `zh-CN`、`en` 头，`HandlerMethodArgumentResolver` 自动填 `Locale` 参数 |
| **Cookie** | `CookieLocaleResolver` | 存 cookie，用户手动切语言 |
| **Session** | `SessionLocaleResolver` | 服务端会话记忆 |
| **URL 参数 `?lang=zh`** | `LocaleChangeInterceptor` + `addInterceptors` | 链接切换语言，前后端分离常用 |

```java
@Configuration
public class LocaleConfig implements WebMvcConfigurer {
    @Bean
    public LocaleResolver localeResolver() {
        return new CookieLocaleResolver("lang");       // 指定 cookie 里语言名
    }
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new LocaleChangeInterceptor());  // 支持 ?lang=zh 切换
    }
}
```

> 关键认知：**`Locale` 是贯穿消息解析的键**。前端带语言的三种通道（Header/Cookie/URL）最终都归并为一个 `Locale`，传给 `MessageSource` 决定用哪份 properties。

## 六、与参数校验异常联动

`@RequestBody` 校验失败抛 `MethodArgumentNotValidException`，也别漏掉，统一进全局处理器：

```java
@ExceptionHandler(MethodArgumentNotValidException.class)
public ResponseEntity<BaseResponse<Void>> handleValid(MethodArgumentNotValidException e) {
    FieldError fe = e.getBindingResult().getFieldError();   // 第一个错误字段
    return BaseResponse.error(2001, fe.getField() + " " + fe.getDefaultMessage());
}
```

校验消息本身的多语言策略：Bean Validation 用自己的 `ValidationMessages_*.properties`，**不自动接 Spring MessageSource**（需自定义 `MessageInterpolator`）——见 **Java参数校验详解**（见知识库）。若想让校验消息也走统一 MessageSource，可自定义 `MessageInterpolator`，属于进阶。

## 七、常见坑

1. **中文乱码**：必须 `spring.messages.encoding: UTF-8`；properties 文件也是 UTF-8 保存，且 `LocaleChangeInterceptor` 默认 `Accept-Language` 头大小写敏感（`zh-CN` 与 `zh-cn` 注意）。
2. **精确匹配陷阱**：`@ExceptionHandler(Exception.class)` 会吞掉业务异常细节——务必**先写具体异常、再写兜底**，且兜底里 `log.error()`。
3. **错误码 vs 文案两张皮**：只改 `messages.properties` 忘了 `ErrorCode` 常量一致 → 前端拿到码却查不到文案（码表要对齐）。
4. **`fallback-to-system-locale`**：默认值依赖服务器系统语言，部署到不同机器可能回退不一致——建议显式配 `false`。
5. **数字码用 String 做 key**：`getMessage` 要求 key 是 String，数字码需 `String.valueOf(code)`（见 5.3）。语义码天然是 String 可免这一步。
6. **兜底异常别把堆栈吞掉**：`handleAll` 至少 `log.error("...", e)`，否则线上查不了原因。

## 八、总结

- **全局异常**：`@RestControllerAdvice` + `@ExceptionHandler` 集中收口，配 `BaseResponse(code/msg/data)` 与业务逻辑解耦。
- **错误码**：数字分段码为主流（前端 switch 稳定），错误码 + 描述存 `messages_*.properties` 配置文件。
- **国际化**：`MessageSource` 按 `Locale` 查多语言 properties；Locale 来自 Header/Cookie/URL 三通道。
- **全链路**：业务 `throw BusinessException(1001)` → advice 用 `messageSource.getMessage("1001", args, locale)` → 返回 `{code:1001, msg:"用户不存在"}`。
