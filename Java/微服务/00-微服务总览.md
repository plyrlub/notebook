# 微服务架构总览

> 版本基线：Spring Boot 3.x / Spring Cloud Alibaba 生态。
> 受众：Java 后端开发，已懂 Spring/SpringBoot。
> **本域定位：微服务架构 = 组件「组合层」**——讲怎么用中间件+框架+网络底座搭建微服务（注册/配置/网关/治理链路）；**具体组件的实现**在各自底座域（中间件/框架/网络底座）。

## 1. 微服务定位：组合层，不是零件库

微服务是**架构思想**（拆分 + 独立部署 + 分布式协同）。**它的零件（Nacos/Apollo/Netty/gRPC 等）已归入各自的底座域**（中间件/框架/网络底座），微服务架构层只讲**组合与编排**：

| 层 | 角色 | 域 |
|---|---|---|
| **网络底座** | 进程通信/Web 服务器 | [00-网络底座总览](../框架/网络底座/00-网络底座总览.md)（Netty/NIO/Tomcat）|
| **框架** | 应用业务框架（Spring/MyBatis/数据访问）| 框架域、[00-ORM全家桶总览与选型](../框架/数据访问层/00-ORM全家桶总览与选型.md) |
| **中间件** | 独立支撑服务（配置/注册/协调）| [00-中间件总览](../中间件/00-中间件总览.md)（Nacos/Apollo/Seata）|
| **微服务架构(本域)** | **怎么组合这些层成微服务** | 注册/网关/治理/链路 |

> 🔑 记忆：**中间件是"零件"，微服务架构是"整机图纸"。** 同一组件（Nacos）的**实现**在中间件 [00-中间件总览](../中间件/00-中间件总览.md)，微服务架构讲它的**用**法。
