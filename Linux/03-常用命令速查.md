# 03-常用命令速查

> **受众**：后端工程师、Linux 基础较弱。本篇按**场景**组织（进程/网络/磁盘/文本/服务），不是字母表背命令——重点是可复制的**命令组合**。
> **版本**：Ubuntu LTS 为主；包管理、服务命令双版本差异标注。
> **定位**：速查手册性质，命令参数给「够用」集，不穷举 man 页。

---

## 学习目标

1. 会用 ps/top/pgrep/kill 管理进程，处理「杀不掉」「找进程」场景

3. 会用 df/du 定位磁盘占用，处理磁盘满
4. 掌握 grep/sed/awk 三剑客的组合用法（本篇重点）
5. 会用 systemctl 管理服务，能读懂/编写最小 service 单元

## 1. 进程管理

### 1.1 查进程

| 命令 | 场景 |
| ---- | ---- |
| `ps aux` | 全量进程列表（CPU/内存占用） |
| `ps aux \| grep java` | 找名字含 java 的进程（经典组合） |
| `pgrep -f java` | 直接输出 PID（比 grep 干净） |
| `pgrep -af java` | 带完整命令行输出 |
| `top` | 实时监控（按 P=CPU、M=内存 排序，q 退出） |

**命令组合（后端高频）**：按端口找进程 → 看占用 → 结束

```bash
# 1. 端口 8080 被谁占用
ss -tlnp | grep 8080            # Ubuntu 新版；-p 显示进程（需 sudo）
lsof -i :8080                   # 另一个视角：文件句柄
# 2. 找到 PID 后看详情 / 结束
ps -fp <PID>
kill <PID>                      # 默认 SIGTERM（15），优雅结束
kill -9 <PID>                   # SIGKILL（9），强杀（慎用：不触发清理逻辑）
```

> ⚠️ **易错点**：`ps aux | grep xxx` 会带出 grep 自身进程——用 `pgrep` 或 `ps aux | grep [j]ava`（方括号技巧）规避；`kill -9` 前先试 `kill`（15），强杀可能留下脏状态。

### 1.2 进程与线程

```bash
top -H -p <PID>                 # 看进程内所有线程的 CPU（排查线程级瓶颈）
ps -T -p <PID>                  # 线程列表
cat /proc/<PID>/status | grep Threads
```

> 排查「进程 CPU 100%」：`top -H -p PID` 找到线程 TID → Java 场景用 `jstack PID | grep TID(16进制)` 定位代码行。

## 2. 网络

| 命令 | 场景 |
| ---- | ---- |
| `ss -tlnp` | 监听端口 + 进程（t=tcp l=listen n=数字 p=进程） |
| `ss -tnp` | 已建立连接（排查连接数） |
| `ss -s` | 连接统计总览 |
| `lsof -i :port` | 谁占用了端口 |
| `curl -v http://x` | 调试 HTTP（-v 看握手/头，-I 只看响应头） |
| `ping / traceroute` | 连通性 / 路由路径 |

**命令组合（端口/连接排查）**：

```bash
# 服务起来了但连不上？
ss -tlnp | grep 8080            # ① 监听了吗
curl -v http://127.0.0.1:8080   # ② 本机通吗（通=防火墙/公网问题）
sudo lsof -i :8080              # ③ 哪个进程（确认没起错服务）
# 连接数统计（排查连接泄漏）
ss -s
ss -tn state established | wc -l
```

> ⚠️ **易错点**：`netstat` 已废弃，用 `ss`；`lsof`/`ss -p` 需要 root 才看得到别人进程的端口占用。

## 3. 磁盘

| 命令 | 场景 |
| ---- | ---- |
| `df -h` | 各分区使用率（磁盘满第一眼） |
| `df -i` | inode 使用率（文件数爆满但 df -h 正常！） |
| `du -sh /path` | 目录总大小 |
| `du -sh /path/* \| sort -rh` | 逐项排序找大头 |
| `lsblk` | 块设备/挂载点总览 |
| `mount` | 当前挂载详情 |

**命令组合（磁盘满排查套路）**：

```bash
df -h                                    # ① 哪个分区满了
du -sh /var/log/* | sort -rh | head      # ② 逐层往下找（日志最常背锅）
# 大文件
find / -xdev -type f -size +1G -exec ls -lh {} \; 2>/dev/null
# 已删除但仍被占用的文件（df 满但 du 找不到——进程持有）
lsof +L1 | grep deleted
```

> ⚠️ **易错点**：磁盘 100% 但 `du` 找不出大头 → 有进程持有已删除文件（`lsof +L1` 找出来重启对应进程即可）；小文件海量时 `df -i` 先满。

## 4. 文本三剑客：grep / sed / awk（重点）

### 4.1 grep：筛选

| 用法 | 场景 |
| ---- | ---- |
| `grep ERROR app.log` | 按关键词过滤 |
| `grep -i` | 忽略大小写 |
| `grep -E "A\|B"` | 扩展正则（多条件） |
| `grep -v xxx` | 排除 |
| `grep -c` | 计数 |
| `grep -rn keyword /path` | 递归搜目录 |
| `grep -A3 -B3` | 上下文各 3 行 |

### 4.2 sed：替换/编辑流

| 用法 | 场景 |
| ---- | ---- |
| `sed -i 's/old/new/g' file` | 就地替换全部（-i 直接改文件） |
| `sed -i 's/old/new/' file` | 只替换每行第一个 |
| `sed -n '10,20p' file` | 打印 10~20 行 |
| `sed '/^#/d' file` | 删掉注释行（只看有效配置） |

> ⚠️ **易错点**：`-i` 直接改原文件，先 `sed 's/.../' file`（不带 -i）试跑确认再上 `-i`；macOS 的 `sed -i` 需要 `-i ''`（BSD 差异），服务器 Linux 无此问题。

### 4.3 awk：按列处理

| 用法 | 场景 |
| ---- | ---- |
| `awk '{print $1}' file` | 取第 1 列 |
| `awk '{print $2, $3}'` | 多列 |
| `awk -F, '{print $1}'` | 按逗号分隔（默认空格） |
| `awk '$3 > 100'` | 按条件过滤行 |
| `awk '{sum+=$3} END{print sum}'` | 求和 |

### 4.4 三剑客组合（本篇精华，直接抄）

```bash
# ① 统计日志里各错误类型出现次数（Top10）
grep -E "ERROR|Exception" app.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -10

# ② 提取某时间段的日志行
sed -n '/2026-08-10 09:00/,/2026-08-10 10:00/p' app.log

# ③ 找出响应时间超过 3s 的请求（假设日志第 5 列是耗时）
awk '$5 > 3000 {print $1, $4, $5}' access.log | sort | uniq -c | sort -rn | head

# ④ 批量替换配置文件并备份
sed -i.bak 's/8080/9090/g' app.yml

# ⑤ 找 IP 出现次数 Top5（日志分析）
grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' access.log | sort | uniq -c | sort -rn | head -5

# ⑥ 排除注释和空行看配置
grep -vE '^\s*#|^\s*$' nginx.conf
```

> 💡 **管道心法**：`grep` 筛行 → `awk` 取列 → `sort | uniq -c | sort -rn` 计数排序 → `head` 取 Top。这套流水线覆盖 80% 的日志分析需求。

## 5. 文件与压缩

| 命令 | 场景 |
| ---- | ---- |
| `find /path -name "*.log"` | 按名找文件 |
| `find /path -mtime -7` | 7 天内修改过 |
| `find /path -size +100M` | 按大小找 |
| `cp -r / rsync -av` | 复制目录 / 增量同步 |
| `tar czf app.tar.gz dir` | 打包压缩 |
| `tar xzf app.tar.gz` | 解包 |
| `unzip / zip` | zip 系列 |

**命令组合（发布/备份）**：

```bash
# 备份带时间戳
tar czf /backup/app-$(date +%Y%m%d_%H%M).tar.gz /var/www/app
# 远程同步（部署）
rsync -avz --delete /local/dist/ deploy@ip:/var/www/app/
```

## 6. systemd 服务管理

### 6.1 常用命令

```bash
systemctl status nginx        # 状态（含最近日志）
systemctl start/stop/restart/reload nginx
systemctl enable nginx        # 开机自启
systemctl enable --now nginx  # 自启 + 立即启动（组合）
systemctl list-units --type=service --state=running   # 所有运行中服务
journalctl -u nginx -n 50     # 服务最近 50 行日志
journalctl -u nginx --since "10 minutes ago"          # 按时间
```

### 6.2 自写 service 单元（部署 Java/Python 必备）

`/etc/systemd/system/myapp.service`：

```ini
[Unit]
Description=My Java App
After=network.target mysql.service        # 依赖顺序

[Service]
User=deploy                               # 用普通用户跑（别用 root！）
WorkingDirectory=/var/www/myapp
ExecStart=/usr/bin/java -jar myapp.jar    # 绝对路径
Restart=on-failure                        # 崩溃自动拉起
RestartSec=5                              # 重启等待
Environment=JAVA_OPTS=-Xmx512m

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload              # 改完单元文件必须 reload
sudo systemctl enable --now myapp
journalctl -u myapp -f                    # 跟日志（-f 实时）
```

> ⚠️ **易错点**：① 改 .service 后忘 `daemon-reload` 导致配置不生效；② ExecStart 用相对路径/环境变量会启动失败；③ 服务崩溃疯狂重启看 `RestartSec`，别用 `Restart=always` 对瞬时故障。

## 8. 最佳实践

1. **先看再杀**：kill 前 `ps -fp PID` 确认没杀错；`kill -9` 是最后手段
2. **日志分析固定流水线**：grep → awk → sort | uniq -c → head，模板直接复用
3. **sed -i 前先试跑**：不带 -i 看输出，确认无误再落盘
4. **服务全部 systemd 化**：别用 `nohup java -jar &` 裸跑（无自启/无日志/无管理），写单元文件
5. **ssh 单条命令跑远端**：`ssh host 'cmd'` 批量巡检神器（配 `~/.ssh/config` 别名更爽）

## 9. 常见踩坑

| 现象 | 原因 | 解决 |
| ---- | ---- | ---- |
| ps 里找不到进程但端口占用 | 进程名被截断/改名 | `ss -tlnp` 或 `lsof -i :port` 反查 PID |
| df -h 100% 但 du 找不到 | 进程持有已删文件 | `lsof +L1`，重启持有进程 |
| 磁盘没满但报 No space left | inode 耗尽 | `df -i` 检查 |
| sed -i 后文件乱了 | 正则写错未试跑 | 先不带 -i 验证 |
| systemctl 改配置不生效 | 没 daemon-reload | `systemctl daemon-reload` |
| nohup 进程被系统杀 | 无守护重启机制 | 改 systemd 单元 |

## 10. 小结

- 进程：`ps/pgrep` 找 → `top -H` 看线程 → `kill` 优雅 / `kill -9` 兜底
- 网络：`ss -tlnp` 是端口排查第一命令；`curl -v` 本机自测二分定位
- 磁盘：`df -h` → `du -sh *` 逐层；inode 与 deleted 文件两个隐藏坑
- 三剑客：grep 筛行、awk 取列、sed 替换；组合流水线解决 80% 日志需求
- 服务：systemd 统一管理，自写单元文件替代裸跑
