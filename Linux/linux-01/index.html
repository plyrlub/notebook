    01-用户管理与登录授权¶

    受众：后端工程师、Linux 基础较弱。本篇学完能独立完成：创建运维账号、配置 sudo 授权、用密钥登录服务器、禁用危险登录方式。
    版本：Ubuntu LTS 为主，CentOS/RHEL 系差异处标注（CentOS: xxx）。
    定位：应用层为主，不追 PAM/内核认证底层，但三文件结构、sudoers 语法这些「必知必会」讲透。

    学习目标¶

    1. 会用 useradd/usermod/userdel/passwd 完成用户生命周期管理
    2. 看得懂 /etc/passwd、/etc/shadow、/etc/group 三个文件的字段含义
    3. 分清 su 与 sudo，能用 visudo 安全编辑授权规则
    4. 能配置 SSH 密钥登录并禁用密码登录、锁定 root 远程登录
    5. 遵循「最小权限 + 独立运维账号」的服务器管理实践

    前置知识¶

    • 本篇无前置；建议先读 00-Linux总览 了解版本差异
    • 全程需要 root 或 sudo 权限：云服务器初始登录一般用 root（Ubuntu 云镜像默认用户 ubuntu，CentOS 默认 root）

    1. 用户与组管理¶

    1.1 核心命令¶

    命令 作用 常用参数
    useradd 创建用户 -m 建家目录、-s 指定 shell、-G 附加组、-u 指定 UID
    usermod 修改用户 -aG 追加组（必须带 -a！）、-s 改 shell、-L/-U 锁定/解锁
    userdel 删除用户 -r 连家目录一起删
    passwd 设置/修改密码 交互式输入，直接带明文会留历史记录，禁用
    id / groups 查看用户/组信息 排查权限问题第一步
    groupadd / groupdel 组管理 —

    命令组合（后端高频）：创建部署用户并加入 sudo 组（Ubuntu）：

    # Ubuntu：sudo 组 = 管理员组
sudo useradd -m -s /bin/bash deploy
sudo passwd deploy                    # 交互式设置密码
sudo usermod -aG sudo deploy          # 追加到 sudo 组（-aG 不可拆成 -G！）

# CentOS：用 wheel 组
sudo useradd -m -s /bin/bash deploy
sudo passwd deploy
sudo usermod -aG wheel deploy

    ⚠️ 易错点：usermod -G sudo deploy 不带 -a 会把用户从其他组移除，只保留 sudo 组。追加组必须 -aG。

    1.2 三个配置文件（必知字段）¶

    文件 内容 关键字段
    /etc/passwd 用户账户信息（所有人可读） 用户名:x:UID:GID:注释:家目录:shell
    /etc/shadow 密码哈希（仅 root 可读） 用户名:哈希:...，! 或 * 表示锁定/无密码
    /etc/group 组信息 组名:x:GID:成员列表

    解读技巧：grep deploy /etc/passwd 看用户存在与否及 shell；grep deploy /etc/group 看用户属于哪些组——排查「为什么没权限」的万能起点。

    💡 用户密码哈希以 ! 开头 = 账户被锁定（passwd -l 效果）；useradd 创建的用户未设密码前 shadow 里是 !，不能登录——这是安全默认，不是 bug。

    1.3 切换用户：su vs sudo（必须分清）¶

    场景 命令 特点
    切到 root 环境 su - 需要 root 密码；- 加载 root 完整环境变量
    切到指定用户 su - deploy 需要 deploy 的密码
    以 root 执行单条命令 sudo <cmd> 需要当前用户自己的密码；只提升单条命令权限
    以 root 执行并保持环境 sudo -E <cmd> -E 保留当前用户环境变量（如代理、PATH）

    最佳实践：
    - 日常操作 sudo 而非 su -：每次授权有日志（/var/log/auth.log），可审计
    - 不要用 sudo su - 图省事——等于长期 root 会话，丢失审计
    - 需要 root 交互环境时用 sudo -i

    2. 授权管理（sudoers）¶

    2.1 sudo 的本质¶

    sudo 不是「密码正确就能 root」，而是按 /etc/sudoers 规则授权。规则写错 = 授权失效或权限失控，所以必须用 visudo 编辑（自带语法校验，改错会拒绝保存，防锁死）。

    2.2 sudoers 语法（读得懂 + 会写最小规则）¶

    # 用户/组  主机 = (以谁身份) 命令白名单
deploy     ALL = (ALL) NOPASSWD: /usr/bin/systemctl restart nginx
%sudo      ALL = (ALL:ALL) ALL
    片段 含义
    deploy / %sudo 用户 / 组（组带 % 前缀）
    第一个 ALL 主机（一般就写 ALL）
    (ALL:ALL) 可切换成的用户:组
    ALL 可执行的命令（白名单写法：逗号分隔命令绝对路径）
    NOPASSWD: 免密前缀（必须大写，且带冒号）

    命令组合（运维常用）：给运维用户免密重启服务 + 看日志权限：

    sudo visudo -f /etc/sudoers.d/deploy    # 独立规则文件（比改主文件安全）
# 内容：
# deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl
# deploy ALL=(ALL) NOPASSWD: /bin/journalctl
# deploy ALL=(ALL) ALL                  # 兜底全权（按需决定要不要）

    ⚠️ 易错点：/etc/sudoers.d/ 下的文件名不能带 .（如 deploy.conf 会被忽略，deploy 才行）；规则文件权限必须 440。

    2.3 Ubuntu sudo 组 vs CentOS wheel 组（版本差异）¶

    • Ubuntu：管理员组是 sudo，sudoers 默认含 %sudo ALL=(ALL:ALL) ALL
    • CentOS/RHEL：管理员组是 wheel，且默认只有 wheel 组能用 su 切 root（PAM 限制）

    最佳实践：新用户进管理员组，Ubuntu 加 sudo，CentOS 加 wheel——写脚本时别写死，双版本都要兼容：

    # 判断式写法（脚本内通用）
if getent group sudo >/dev/null; then GROUP=sudo; else GROUP=wheel; fi
sudo usermod -aG "$GROUP" deploy

    3. SSH 登录配置¶

    3.1 密钥登录（一次性配置，永久免密）¶

    服务器端（以 deploy 用户执行）：

    mkdir -p ~/.ssh && chmod 700 ~/.ssh
touch ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys
echo "ssh-ed25519 AAAA...你的公钥" >> ~/.ssh/authorized_keys

    本地端（生成密钥，Windows 用 Git Bash / macOS 自带）：

    ssh-keygen -t ed25519 -C "deploy@aliyun"    # 现代默认：ed25519 优于 rsa 2048
ssh-copy-id deploy@服务器IP                  # 一键推送公钥（自动处理权限）

    ⚠️ authorized_keys 权限三连：目录 700、文件 600、属主是登录用户。权限过宽（如 644）SSH 会直接拒绝使用该文件——这是排障第一检查点。

    3.2 加固登录（上线必做）¶

    编辑 /etc/ssh/sshd_config：

    PermitRootLogin no              # 禁止 root 直接 SSH（Ubuntu 默认已禁）
PasswordAuthentication no       # 禁用密码登录，只留密钥
PubkeyAuthentication yes
AllowUsers deploy               # 只允许指定用户登录（白名单）

    生效：sudo systemctl restart sshd（Ubuntu 服务名 ssh，CentOS 是 sshd——restart 前先 sshd -t 校验语法，防把自己锁外面）

    sudo sshd -t && sudo systemctl restart sshd

    ⚠️ 易错点：改 sshd_config 前先开一个新终端验证密钥能登录再重启；PasswordAuthentication no 后忘记配置密钥 = 永久锁死服务器（只能靠云厂商控制台 VNC 救）。

    3.3 常用 SSH 参数速查¶

    场景 命令/参数
    端口非 22 ssh -p 2222 deploy@ip
    指定密钥文件 ssh -i ~/.ssh/deploy_key deploy@ip
    本地端口转发（跳板机） ssh -L 3306:内网DB:3306 deploy@跳板机
    免交互执行远端命令 ssh deploy@ip 'systemctl status nginx'

    4. 最佳实践¶

    1. 独立运维账号：不用 root 日常操作；每人一个账号（zhangsan 而非共享 admin）——审计日志才能定位到人
    2. 最小权限：能白名单命令就白名单，NOPASSWD 只给高频固定命令；兜底 ALL 按需再开
    3. 密钥优先：密码登录默认关闭；密钥文件用 ed25519，私钥本地权限 chmod 600
    4. root 策略：云服务器 PermitRootLogin no + 密钥登录；本地虚拟机可以保留密码登录方便调试
    5. 改名/删号纪律：离职/换人删除账号 sudo userdel -r zhangsan，并查 lastlog 确认无残留登录
    6. sudo 日志留痕：Ubuntu 看 /var/log/auth.log，CentOS 看 /var/log/secure——出问题先查这里

    5. 常见踩坑¶

    现象 原因 解决
    usermod 后用户失去其他组权限 -G 未带 -a 覆盖了附加组 用 -aG
    密钥正确但 SSH 拒绝 authorized_keys 权限 644 chmod 600 + 目录 700
    useradd 后无法登录 密码未设置（shadow 为 !） passwd <user>
    重启 sshd 后连不上 配置语法错误 先 sshd -t 再 restart
    sudo 报 deploy is not in the sudoers file 未加入管理员组 Ubuntu usermod -aG sudo / CentOS wheel
    新用户 shell 是 sh useradd 未指定 -s usermod -s /bin/bash deploy

    6. 小结¶

    • 用户管理三件套：useradd -m -s -G / usermod -aG / passwd；排障先看三文件
    • 授权体系核心是 sudoers：visudo 编辑、/etc/sudoers.d/ 独立规则、Ubuntu sudo 组 / CentOS wheel 组
    • SSH 安全三要素：密钥登录 + 禁密码 + 禁 root；sshd -t 校验是重启前铁律
    • 一切操作留审计：/var/log/auth.log（Ubuntu）/ /var/log/secure（CentOS）
