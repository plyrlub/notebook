# 05-安全加固

> **受众**：后端工程师、Linux 基础较弱。本篇是服务器上线前的安全基线：SSH 加固、防火墙配置、日志审计与登录监控。
> **版本**：Ubuntu LTS（ufw）/ CentOS（firewalld）双版本命令都给。
> **定位**：给「能跑就行」到「可上线」的差距补课；不追 SELinux/AppArmor 内部策略语言细节，但开启状态与基本策略讲清楚。

---

## 学习目标

1. 会按清单加固 SSH（禁 root / 禁密码 / 白名单）
2. 会用 ufw（Ubuntu）和 firewalld（CentOS）放行/拦截端口
3. 会读关键日志，配置登录失败告警
4. 了解 SELinux / AppArmor 的存在与基本操作（不深挖）
5. 能对一台新服务器完成 10 分钟安全基线加固

## 1. SSH 加固清单（上线第一件事）

编辑 `/etc/ssh/sshd_config`：

```ini
Port 2222                      # ① 换默认端口（22 被扫描最多）
PermitRootLogin no             # ② 禁 root 直登
PasswordAuthentication no      # ③ 禁密码（必须先配好密钥！）
PubkeyAuthentication yes
AllowUsers deploy              # ④ 登录白名单
MaxAuthTries 3                 # ⑤ 最大认证尝试
LoginGraceTime 30              # 认证超时
```

应用配置（**先 `sshd -t` 校验 + 新终端验证密钥，再重启**）：

```bash
sudo sshd -t && sudo systemctl restart sshd    # Ubuntu 服务名 ssh / CentOS sshd
```

**命令组合（一键加固脚本骨架）**：

```bash
#!/bin/bash
set -e
# 1. 创建运维账号
sudo useradd -m -s /bin/bash deploy
echo "deploy:<强密码>" | sudo chpasswd
sudo usermod -aG sudo deploy          # CentOS: wheel
# 2. 推送公钥（运维主机的 key）
mkdir -p /home/deploy/.ssh && chmod 700 /home/deploy/.ssh
echo "ssh-ed25519 AAAA... <注释>" >> /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh && chmod 600 /home/deploy/.ssh/authorized_keys
# 3. 加固 sshd_config（先备份）
sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak
sudo sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo sshd -t && sudo systemctl restart sshd
```

> ⚠️ **易错点**：顺序必须是「先配好密钥并验证 → 再禁密码 → 最后禁 root」，倒过来会把自己锁在门外；云服务器控制台 VNC 是最后逃生通道，别关。

## 2. 防火墙（双版本）

### 2.1 Ubuntu：ufw

```bash
sudo ufw default deny incoming     # 默认拒绝入站
sudo ufw default allow outgoing    # 出站放行
sudo ufw allow 22/tcp              # SSH（若换了端口写对应）
sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
sudo ufw allow 3306/tcp from 10.0.0.0/8   # 数据库只放内网段
sudo ufw enable                    # 启用（⚠️ 会断现有连接，先确认 SSH 规则）
sudo ufw status verbose
```

### 2.2 CentOS：firewalld

```bash
sudo systemctl enable --now firewalld
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --permanent --add-port=80/tcp
sudo firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=10.0.0.0/8 port port=3306 protocol=tcp accept'
sudo firewall-cmd --reload          # 永久规则生效
sudo firewall-cmd --list-all        # 查看
```

> ⚠️ **易错点**：ufw/firewalld 启用的瞬间可能断 SSH——**先加 SSH 放行规则再 enable**；云服务器还有一层安全组（云厂商控制台），两层都要配；端口不通排查顺序：本机 curl → 防火墙 → 云安全组。

## 3. 日志审计

### 3.1 关键日志位置

| 日志 | 内容 |
| ---- | ---- |
| `/var/log/auth.log`（Ubuntu） | 认证日志：登录/ssh/sudo |
| `/var/log/secure`（CentOS） | 同上 |
| `/var/log/syslog`（Ubuntu） | 系统日志 |
| `/var/log/messages`（CentOS） | 同上 |
| `/var/log/journal/` | journald 二进制日志（journalctl 查） |

### 3.2 登录审计命令

```bash
who / w / users           # 当前在线
last                      # 最近登录历史（含来源 IP）
lastb                     # 登录失败记录（需 root）
lastlog                   # 每个用户最后登录时间
journalctl -u ssh -n 50   # ssh 服务日志
```

**命令组合（登录监控）**：

```bash
# 最近失败的 SSH 登录（暴力破解线索）
sudo grep "Failed password" /var/log/auth.log | tail -20
# 来源 IP Top10
sudo grep "Failed password" /var/log/auth.log | grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' | sort | uniq -c | sort -rn | head -10
# 当前登录用户 + 来源
who -u
```

### 3.3 登录失败告警（fail2ban）

暴力破解是常态，fail2ban 自动封 IP：

```bash
sudo apt install -y fail2ban        # CentOS: dnf install -y fail2ban
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
# jail.local 里配置：
# [sshd]
# enabled = true
# maxretry = 5        # 5 次失败
# bantime = 3600      # 封 1 小时
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd    # 查看封禁状态
```

> 💡 更轻的替代：日志里发现爆破 → 手动加防火墙规则封 IP：`sudo ufw deny from <IP>`（ufw）/ `sudo firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=<IP> drop' && sudo firewall-cmd --reload`（firewalld）。

## 4. SELinux / AppArmor（了解级）

| 发行版 | 默认 MAC 机制 | 作用 |
| ---- | ---- | ---- |
| CentOS/RHEL | **SELinux**（enforcing） | 进程级强制访问控制；新装服务常遇「权限对但拒绝」 |
| Ubuntu | **AppArmor** | 应用级限制（如 nginx/sshd profile） |

**SELinux 最小操作**（CentOS 必知）：

```bash
getenforce                 # Enforcing=开启 / Permissive=放行但记录 / Disabled
setenforce 0               # 临时放行（重启失效）——排障第一步确认是不是它挡的
# 永久关闭：/etc/selinux/config 里 SELINUX=disabled
# 正确姿势（别关闭）：用 audit2allow 放行具体规则
grep denied /var/log/audit/audit.log | audit2allow -M mypol && semodule -i mypol.pp
```

**AppArmor 最小操作**（Ubuntu）：

```bash
aa-status                  # 查看 profile 状态
sudo aa-complain /usr/sbin/nginx   # 临时放行模式（记录不阻止）
sudo aa-disable /usr/sbin/nginx    # 禁用（排障用，别长期关）
```

> ⚠️ **易错点**：CentOS 新装服务（如自定义端口 nginx）报「权限被拒」且权限位没问题 → 先 `setenforce 0` 试，确认是 SELinux 后**用策略放行**而非长期关闭；生产别 Disabled，这是 RHEL 系安全基线硬要求。

## 5. 其他加固项

```bash
# ① 定期全量更新补丁
sudo apt update && sudo apt upgrade -y        # Ubuntu
sudo dnf update -y                            # CentOS

# ② 无用服务排查
systemctl list-units --type=service --state=running | grep -vE 'systemd|dbus|sshd|network'

# ③ 关键文件只读保护（可选）
sudo chattr +i /etc/ssh/sshd_config           # 防误改（-i 解除）

# ④ 账户密码策略（/etc/login.defs）
# PASS_MAX_DAYS 90   PASS_MIN_DAYS 7   PASS_WARN_AGE 14

# ⑤ 命令历史加固（可选）
echo "export HISTTIMEFORMAT='%F %T '" >> ~/.bashrc   # 历史带时间戳
```

## 6. 安全基线检查清单（新服务器 10 分钟版）

- [ ] 创建独立运维账号（非 root），加入管理员组
- [ ] SSH 密钥登录配置完成，**密码登录已禁用**，root 直登已禁
- [ ] SSH 端口已改（或至少确保 Fail2ban 保护 22）
- [ ] 防火墙已启用，只放行必要端口；数据库端口限内网
- [ ] fail2ban 已装并监控 sshd
- [ ] 系统补丁已更新
- [ ] 登录日志可读，`lastb` 无异常堆积

## 7. 常见踩坑

| 现象 | 原因 | 解决 |
| ---- | ---- | ---- |
| 加固后连不上服务器 | 禁密码/禁 root 顺序反了 | 云控制台 VNC 登录恢复 |
| 端口放了但外面不通 | 云安全组没放行 | 控制台安全组规则检查 |
| CentOS 服务权限拒绝 | SELinux 拦截 | setenforce 0 确认 → audit2allow 放行 |
| ufw enable 断线 | 忘了先放 SSH | 先 allow 22 再 enable |
| 服务器被爆破 | 密码登录/默认端口 | 禁密码 + 换端口 + fail2ban |

## 8. 小结

- SSH 三禁：禁 root、禁密码、禁默认端口；顺序：先密钥后禁用
- 防火墙原则：默认拒绝入站 + 白名单放行；ufw / firewalld 双版本要会
- 日志审计：auth.log/secure + last/lastb；fail2ban 自动封爆破 IP
- SELinux/AppArmor 是「权限对但拒绝」的头号嫌疑人，学会用放行而非关闭
- 新服务器 10 分钟检查清单跑一遍再上线
