# 02-文件权限与属主

> **受众**：后端工程师、Linux 基础较弱。本篇学完能独立处理：权限报错排查、批量授权、特殊权限位与 ACL 使用、危险权限巡检。
> **版本**：Ubuntu LTS 为主，命令双版本通用（权限体系两发行版无差异）。
> **定位**：应用层为主，不追 inode/ACL 内核实现，但权限位语义、特殊位、ACL 覆盖场景讲透。

---

## 学习目标

1. 能逐字段解读 `ls -l` 输出，掌握 chmod 数字/字母两套写法
2. 会用 chown/chgrp 修正属主属组，理解 umask 对新建文件的影响
3. 分清 SUID/SGID/Sticky 三个特殊位的用途（为什么 /tmp 是 1777）
4. 会用 ACL（setfacl/getfacl）解决「多用户共享目录」问题
5. 会巡检危险权限（find -perm）并修复

## 1. 权限模型：读/写/执行

### 1.1 ls -l 逐字段解读

```
-rwxr-xr-- 1 deploy deploy 4096 8月10 09:00 app.sh
│ └┬┘ └┬┘ └┬┘ │  │     │    │        │
│  类型 属主 属组 其他 链接 属主 属组  大小     文件名
```

- 第一个字符：`-` 普通文件 / `d` 目录 / `l` 软链接 / `b`/`c` 块/字符设备
- 三段权限：属主(u) / 属组(g) / 其他人(o)，每段 `rwx` 三字符，缺位为 `-`

### 1.2 权限对文件 vs 目录（必须分清）

| 权限 | 对文件 | 对目录 |
| ---- | ---- | ---- |
| r（读） | 读文件内容 | 列出目录下的文件名 |
| w（写） | 修改文件内容 | 创建/删除/重命名目录内文件 |
| x（执行） | 运行文件 | **进入目录**（cd 的前提） |

> ⚠️ **易错点**：目录只有 r 没有 x，能 ls 但 cd 不进去；`chmod 644 dir` 后目录内容可读但无法进入——给目录授权通常是 `755`（rx 一起给）。

---

## 2. chmod：改权限

### 2.1 数字写法（八进制）

| 值 | 含义 | 组合 |
| ---- | ---- | ---- |
| 4 | 读 r | 7 = rwx（4+2+1） |
| 2 | 写 w | 6 = rw |
| 1 | 执行 x | 5 = rx |

`chmod 750 file` = 属主 rwx、属组 rx、其他人无。三位数字分别对应 u/g/o。

### 2.2 字母写法（增量/减量）

| 语法 | 含义 |
| ---- | ---- |
| `chmod u+x file` | 给属主加执行位 |
| `chmod g-w file` | 去掉属组写位 |
| `chmod o= file` | 其他人权限清零 |
| `chmod a+x file` | 所有人加执行（a=all） |

**最佳实践**：
- 配置文件 `644`，脚本/二进制 `755`，密钥类 `600`
- 批量修改：`chmod -R 755 /path`（递归），但**慎用**——会覆盖已有精确权限；目录和文件分开处理更稳：
  ```bash
  find /app -type d -exec chmod 755 {} \;
  find /app -type f -exec chmod 644 {} \;
  ```

---

## 3. chown / chgrp：改属主属组

| 命令 | 作用 |
| ---- | ---- |
| `chown deploy file` | 改属主 |
| `chown deploy:deploy file` | 同时改属主:属组（推荐写法） |
| `chgrp dev file` | 只改属组 |
| `chown -R deploy:deploy /app` | 递归改整个目录树 |

**命令组合（部署场景）**：代码发布后统一授权给运行用户：

```bash
sudo chown -R deploy:deploy /var/www/app
sudo find /var/www/app -type d -exec chmod 755 {} \;
sudo find /var/www/app -type f -exec chmod 644 {} \;
```

> ⚠️ 注意：**先 chown 再 chmod**——chown 会清除 SUID/SGID 位（安全设计），顺序反了特殊位会丢。

---

## 4. umask：新建文件的默认权限

- `umask` 是「默认**减去**的权限」：文件默认 `666 - umask`，目录默认 `777 - umask`
- 常见值：`022`（文件 644/目录 755）、`002`（组内协作，文件 664/目录 775）、`077`（私有，文件 600）

```bash
umask                # 查看当前值
umask 022            # 临时设置（当前 shell 有效）
```

**最佳实践**：共享部署目录给 `002`，让同组同事新建文件组内可写；个人目录 `077`。改默认值写进 `~/.bashrc`（用户级）或 `/etc/profile`（全局）。

---

## 5. 特殊权限位：SUID / SGID / Sticky

| 位 | 数字写法 | 字母写法 | 作用 | 典型场景 |
| ---- | ---- | ---- | ---- | ---- |
| SUID | 4xxx | `u+s` | 执行时以**文件属主**身份运行 | `/usr/bin/passwd`（属主 root，普通用户改自己密码） |
| SGID | 2xxx | `g+s` | 目录内新建文件继承目录属组 | 共享协作目录 |
| Sticky | 1xxx | `o+t` | 目录内文件只能被属主/root 删除 | `/tmp`（1777） |

**命令**：`chmod 4755 file`（SUID）、`chmod 2775 dir`（SGID）、`chmod 1777 /tmp`（Sticky）；查看：`ls -l` 里 `s`/`t` 小写 = 同时有 x，大写 `S`/`T` = 无 x。

> ⚠️ **易错点**：`chmod 777` 是万恶之源——配合 SUID 更危险（任何人以 root 跑该程序）。巡检重点：全盘找属主 root 且带 SUID 的非系统文件。

---

## 6. ACL：细粒度权限（多用户协作刚需）

chmod 只有 u/g/o 三档，多个用户要不同权限就得靠 ACL——给**任意用户/组**单独授权。

| 命令 | 作用 |
| ---- | ---- |
| `setfacl -m u:deploy:rwx /data` | 给 deploy 用户加 rwx |
| `setfacl -m g:dev:rx /data` | 给 dev 组加 rx |
| `setfacl -m d:u:deploy:rwx /data` | 设置**默认 ACL**（目录内新建文件自动继承） |
| `setfacl -x u:deploy /data` | 移除某条 ACL |
| `getfacl /data` | 查看 ACL（`ls -l` 权限位末尾会多个 `+`） |

**场景示例**：`/data` 目录由 deploy 用户管理，但测试组 testers 需要只读：

```bash
sudo setfacl -m g:testers:rx /data
sudo setfacl -m d:g:testers:rx /data     # 新建文件也继承只读
getfacl /data                             # 验证
```

> ⚠️ **易错点**：① 默认 ACL 用 `d:` 前缀；② ACL 生效优先级：属主 > 具名用户 > 属组 > 具名组 > 其他；③ 文件系统需挂载支持（ext4/xfs 默认支持，无需配置）。

## 7. 危险权限巡检（安全基线）

```bash
# 全盘找属主 root 且带 SUID 的可疑文件（重点非系统目录）
find / -perm -4000 -user root -type f 2>/dev/null | grep -vE '^/(usr|bin|sbin|lib)/'

# 找全局可写文件（非 /tmp 等合法位置）
find / -perm -002 -type f 2>/dev/null | grep -vE '^/(tmp|proc|sys|dev)/'

# 找无属主文件（用户已删但文件还在）
find / -nouser -o -nogroup 2>/dev/null | grep -vE '^/(proc|sys|dev)/'
```

发现可疑项：确认后 `chmod 755`/`chown` 修正，或从「目录+w 位」层面收敛（删掉目录的 o+w）。

---

## 8. 最佳实践

1. **按角色建组**：`dev`/`testers`/`ops` 组对应权限档，人走改组成员即可，不动文件权限
2. **目录 755 + 文件 644 是基线**，脚本 755、密钥 600；特殊需求再增量
3. **共享目录用 SGID + 默认 ACL**，不用 777 凑合
4. **发布脚本里 chown/chmod 固化**进部署流程，杜绝手动授权不一致
5. 巡检命令挂 cron 每周跑一次，输出发到监控群

## 9. 常见踩坑

| 现象 | 原因 | 解决 |
| ---- | ---- | ---- |
| `Permission denied` 但权限看着对 | 目录缺 x 位 | 检查路径上每级目录权限 |
| 目录能 ls 不能 cd | 目录只有 r 无 x | `chmod 755 dir` |
| chown 后特殊位消失 | chown 会清 SUID/SGID | chown 之后再 chmod 设特殊位 |
| 文件 777 还很安全？ | 全局可写可被篡改 | 收成 755/644，用 ACL 补协作 |
| ACL 加了对但不生效 | 顺序优先级问题 | 属主 > 具名用户 > 属组 > 具名组 |
| `find -perm -4000` 全是系统文件 | 正常系统 SUID 白名单 | 重点查非 /usr/bin 等系统目录的 |

## 10. 小结

- 权限模型：u/g/o 三档 × rwx 三位；**目录的 x = 进入权**是最常被忽略的点
- 三件套：`chmod`（数字/字母）、`chown 属主:属组`、`umask` 控制默认
- 特殊位三兄弟：SUID（借身份）、SGID（继承组）、Sticky（防删他人文件）
- 多用户共享 → ACL（`setfacl -m` + 默认 ACL `d:`），别再 777
- 巡检命令 `find -perm -4000 / -002` 挂 cron，安全基线常态化
